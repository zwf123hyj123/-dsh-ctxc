# release 2026-11-28-3 · 模块归属与监护闭环

> 承接 2026-11-28-2（监督链闭合）。这一版解决的是**模块该由谁拉起**，以及由此暴露的三个真 bug。

## 一、装配

| 目录 | 内容 |
|---|---|
| `bin/dsh` | 容器入口壳：启停、端口仲裁、stop 标记时效、引擎树清理、断点广播、下挂预注入、常驻巡逻 |
| `brain/` | 13 个模块脚本（监工、壳下挂、看门狗、断点、体检、通知、小模型…） |
| `docs/` | 模块清单、采集规范、脑干与意识（R-27/28）、队列与工具表 |

## 二、这一版踩的三个 bug（都写进判据了）

1. **`wait` 会把监工变成摆件**：引擎 `&` 起来后立刻 `wait`，引擎活着的整段时间巡逻代码被堵住。改 `while kill -0` 轮询。
2. **函数定义在分派之后**：`dsh restart` 调不到 `_dsh_stop_clean`，脚本照样打印「已停机清理」——**假成功比报错更难查**。函数已前置。
3. **两个拉起者**：监工和壳同时拉引擎，两个都带 `--port 3080`，只有一个能绑。改成「只要壳在，监工只清不拉」。
4. **热改不生效**：长驻的 `sh` 按旧偏移读脚本，改文件它读不到新行（判断 155）。凡改壳逻辑，必须配一条不依赖壳的兜底，并等一次容器级重启。

## 三、模块归属（详见 `docs/模块清单.md`）

- 长驻模块：**只挂壳或 PID 1**；PPID 出现别的值就当临时进程。
- 按需脚本：不进常驻名单，谁需要谁跑。
- 代码型插件：不是进程，随引擎加载。

## 四、安装

```sh
cp bin/dsh /usr/local/bin/dsh && chmod +x /usr/local/bin/dsh
mkdir -p /root/workspace/记忆档案
cp brain/*.py /root/workspace/记忆档案/
cp docs/* /root/workspace/记忆档案/
sh -n /usr/local/bin/dsh
```

重启后核对：`ps -eo pid,ppid,cmd | grep "bin.js web"` 的 PPID 应是壳；杀任一常驻，5 秒内应被补回。

## 五、边界

- 壳自己由容器收养，容器层不归本包管。
- 宿主侧证据走 DSH App 的手机桥（`diagnostics`），不需要 Shizuku；`android_shell` 需要。
- 本地模型 3B 与云端通道均按此机环境配置，换机需重配。
