## 四、进程搬家四步（引路人 2026-11-28 定的顺序）

要动一个「挂在引擎下」的常驻进程，照这个顺序，别跳步：

1. **先记一下**：在第二节表里写明它现在挂哪、挪到哪、为什么。
2. **挂引擎上**：确认它当前父进程是引擎（`ps -eo pid,ppid,cmd`），这样引擎重启会把它一起带走——不留旧实例在跑。
3. **重启**：`dsh restart`（广播→接续区→换引擎），旧实例随引擎消失。
4. **拉回壳上**：在 `/usr/local/bin/dsh` 的 `web` 分支里加 `setsid nohup python3 -u <脚本>`，且带 `ps ... | grep -F -q <名字>` 去重——壳每次拉起引擎都会检查一次，缺了就补。

已经搬过的：`壳下挂.py`、`通道看门狗.py`。它们的父进程应是 1（或壳），**不是引擎**。

## 五、插件挂在谁名下（2026-11-28 答复）

**两种，别混。**

- **代码型插件**（profile 里那 20 个 npm 包：`dsh-live-compact`、`dsh-hippocampus`、`dsh-our-free-model`、`dsh-im`…）
  它们**不是进程**，是引擎进程里加载的代码。挂在引擎里是**对的**——引擎重启，它们跟着重新加载，不需要搬、也搬不走。
  判据：`ps` 里看不到它们单独的 pid；出问题看引擎启动日志，不看进程表。

- **进程型常驻**（我们自己起的：`虚拟对话`、`虚拟引擎`、`eigenflux dispatch`、`壳下挂`、`通道看门狗`）
  这些才有归属问题，规则见第四节：**只挂壳或 PID 1**，挂引擎下的一律算临时。

**体检怎么分**：`工具体检.py` 里「进程」项只查进程型；代码型查的是「配置里有没有、启动日志里有没有加载成功」，两套判据不混用。
