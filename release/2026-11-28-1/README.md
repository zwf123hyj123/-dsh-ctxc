# 2026-11-28-1 · 让「重启」不再要人

## 解决的问题

Android proot 里跑 Harness，入口脚本原来是 `exec node … dsh web`。
`exec` 会把 node 顶成容器里的**顶层进程**——于是 `kill` 引擎 = 容器结束，虚拟引擎、ollama、dispatch 全部陪葬。
容器内做任何自救都跳不出这一层：setsid、双 fork、看护脚本，容器一重启全清。

## 做法

把容器入口从「引擎本身」换成「看护引擎的壳」：

```
容器入口 sh (/usr/local/bin/dsh web)
   └─ 循环: node … dsh web        ← 引擎降为子进程
        记录 exit code 与运行时长
        3 秒后重新拉起
```

从此 `kill 引擎pid` 只是重启引擎，3 秒后自己回来，容器与常驻进程不受影响。

## 三条必须写死的规则（都是踩出来的）

1. **谁有权停，要显式**：不能用「退出码 0 且活过 30 秒」当主动关闭——`kill -TERM` 也是干净退出（code 0），壳会把「我要重启」读成「你主动关机」，自己 break，容器跟着死。改成只看标记文件 `/tmp/dsh-stop.marker`：有标记才退，其余一律拉起。
2. **两个拉引擎的会打架**：壳和外部守护者同时拉，抢不到 3080 的那个 `exit=1`，壳 3 秒后再拉 → 崩循环。壳拉起前先探端口，已开就等，不抢。
3. **重启完页面不会自己回来**：机器能自愈，人还得手动刷，等于没省人工。前端 `index.html` 注入一段探活：每 2 秒取同源 `manifest.webmanifest`（不依赖引擎状态），连续 2 次失败后一旦恢复就 reload 一次。

## 安装

```sh
sh install.sh          # 每处覆盖前先备份成 .bak-<时间戳>，最后自验四项
```

自验四项：壳 `sh -n`、前端探活代码在位、profile YAML 可解析且含 `agent-default-model`、脑子脚本逐个 `ast.parse`。

## 命令

```sh
dsh status     # 壳 / 引擎 / 3080 / 常驻
dsh restart    # 只重启引擎（推荐日常用）
dsh stop       # 写停止标记并结束引擎，壳退出（= 应用级关闭）
dsh start      # 清标记并拉起（脱离当前会话）
```

## 边界（别当成万能）

- **只覆盖通过 `/usr/local/bin/dsh` 启动的部署**；其它入口还是老行为。
- **App 内嵌 WebView** 不在前端自恢复的覆盖范围，那只管浏览器页面。
- 有 service worker 缓存时，`reload()` 可能拿到旧页，第一次仍建议手动刷。
- 首次部署仍需一次容器级重启：当前容器的顶层就是旧 `exec` 出来的 node，壳要等下一次启动才接管。

## 证据

- 壳日志：`engine exit=0 运行=370s` → 2 秒后新实例，常驻 pid 未变。
- 发布包 sha256 见 `MANIFEST.md`。
