第二版。第一版解决「kill 引擎不必杀容器」，这一版解决**监督链的闭合**：
补人的自己没人补，兜底层自己不在——这类事不解决，前面的都会退回去。

## 三条这次才想明白的

1. **干净退出 ≠ 主动关闭。** 用退出码兼职表达意图，就会把「我要重启」读成「你关机」。停机只认显式标记。
2. **守护循环里不许阻塞。** `wait` 会让守护变成摆件——引擎活着的每秒钟它都没在看。改成轮询存活再收尸。
3. **互盯能抹掉单点。** 监工 5 秒看壳下挂，壳下挂 60 秒看监工；实测双向都能拉回。只有同时死（容器重启）才靠壳接手。

## 边界（照实写）

- 壳自己是被容器收养的孤儿，那层碰不到。
- 长驻脚本热改不生效：改壳要等一次容器级重启。
- 首次部署仍需一次容器级重启（旧入口是 `exec node`）。
- 前端自动刷新依赖壳写的 `reload.json`；App 内嵌 WebView 不在覆盖范围。
